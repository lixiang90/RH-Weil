## CI 故障证据

最近连续三次远程运行均在 `inspect_b1e_response_support.py` 的同一处失败：
`frozen surrogate energy upper is too small`，不是 TeX 路径、依赖安装
或工作流超时。

| 运行 | 提交 |
|---|---|
| [33974211760](https://github.com/lixiang90/RH-Weil/actions/runs/33974211760) | `1062a28` |
| [33971402853](https://github.com/lixiang90/RH-Weil/actions/runs/33971402853) | `28f79ed` |
| [33968494875](https://github.com/lixiang90/RH-Weil/actions/runs/33968494875) | `eca74cc` |

CI 使用 Python 3.11，本地生成原冻结证书的环境使用 Python 3.14。
对同一组 binary64 基础原子的复数 `sum`，总质量实部的结果为：

| 规则 | 总质量的十六进制表示 |
|---|---|
| Python 3.11 内置复数 `sum` | `-0x1.4da3f21c774e6p-2` |
| Python 3.14 内置复数 `sum` | `-0x1.4da3f21c774e2p-2` |
| 显式实部/虚部 `math.fsum`（上述两个环境） | `-0x1.4da3f21c774e2p-2` |

这改变了后续响应多项式的有限浮点替身，故不能直接用旧替身的冻结上界
认证它。Python 官方说明 3.14 改变了复数求和的算法；
这与隔离重放实验一致。[Python 官方文档](https://docs.python.org/3.14/library/functions.html#sum)

这不是增大误差容差、跳过证书或把 CI 强制切换到较新 Python。

新增小型十六进制基础原子回归，独立有理数参考，以及生产代码/
误差重放一致性测试；Python 3.11、3.14 均通过。
在原先失败的本地 Python 3.11 环境，修复后完整 B1e 检查通过，
且得到与 Python 3.14 相同的原冻结上界。

工作流保留 Python 3.11 和原完整已注册检查清单，新增目录检查与
求和回归、打印数值运行时版本，并使用无缓冲入口输出。
依赖范围不变。全套远程验收以修复提交对应的 Actions 结论为准；
提交前的局部通过不代替远程全套成功。

该修复不声称任意平台浮点计算按位相同：其他基础浮点运算若发生变化，
仍必须由原区间证书重新验收，不能靠上述回归自动放行。
