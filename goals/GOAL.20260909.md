\[
 C_0=\frac32-\frac1{\sqrt2}\cot(1/\sqrt2)
 =0.6725007036794116\ldots.

\[

- [O]：开放输入或待完成的审查任务。

另列字段：RH/GRH 等强性、新颖性、外部发表/评审状态、本项目核查范围。一条形式蕴含可为 [T]，其 zeta 实例仍为 [C/O]。

作者主张、已有证明等待审查、真正缺少证明三者分开。未完成外部评审不等于数学上已有反例；引用外部已证定理也不等于引入未证数学假设。DOI、平台、作者使用的工具或通过 CI，都不单独决定可靠性。

复核记录须包含实际核读范围、复跑命令、输出、异议和处理。内部模型交叉审计按实际方式描述，不称为外部同行评审。

## 八、文献随时归档与持续维护

**研究中一旦发现相关文献、修订版本、勘误或关键证明附件，就在当前研究轮次及时保存，不等到论文整理或周期结束。**

统一使用 [RH-Weil/literature/](../literature/README.md)：

1. 保存公开可获取的原始 PDF；重要结论若只在补充文档、TeX、权表、验证器或证书中出现，同时保存必要附件或固定版本链接。保留原文件，不改写原文的结论和状态。
2. 即时更新 literature/README.md 和 manifest.json，记录作者、准确标题、日期、版本或完整 Git 提交、来源页、下载直链、本地路径、获取时间、SHA-256、页数及可读性状态。
3. 按基础证明、方法背景、待审后续、条件结果和未核查主张分类；另记本项目读了哪些部分、验证了什么、哪些依赖尚未检查。
4. arXiv 固定版本号，GitHub 固定提交，Zenodo 固定记录。新版本使用可区分的文件名并记录替代关系；发现勘误时更新依赖它的研究笔记和结论状态。
5. 核查 PDF 的实际标题、作者和正文常数。README、摘要或仓库描述更新后，附带 PDF 可能仍是旧稿；分别归档并准确引用。
6. 无法取得全文时，当轮保存来源链接、元数据和获取状态，后续有条件时补齐。封存或撤回材料只记录状态及可公开取得的版本，不将其计为已证结论。
7. 文献引用进入主证明或用于判断新颖性之前，回到原文核对定理号、假设、误差、统一性与勘误。下载成功、日志 PASS 和局部 Lean 通过均须保留各自边界。
8. 原始扫描件的来源若明确限制向其他仓库复制，完整PDF保留本地，Git保存来源、版本、哈希和保存范围；不移除封面或改写原件来规避该限制。

文献索引是持续维护的检索入口；305 是本次核查的历史快照。以后前沿变化时添加带日期的核查记录，不覆盖旧版本的来源事实。

## 九、定期 commit 并推送 GitHub

**研究过程中持续保存成果，并定期 commit、推送至 RH-Weil 的 GitHub 仓库。**

目标仓库：<https://github.com/lixiang90/RH-Weil>。本地 Git 根目录为 RH-Weil/，已核对 origin 指向该仓库。执行保存时使用当前研究分支及其正确上游。

保存节奏：

- 完成一项独立可复核的结果、重要纠错、失败审计或一批文献归档后，及时形成一次内容明确的 commit。
- 连续研究通常不超过两个有实质变更的轮次而不提交；每个研究周期结束时完成 commit 并 push。
- 准备结束工作或交接时，将未完成证明、开放问题、复现命令和下一步落盘，再提交并推送。重大成果或重要修正提交后及时推送，不必等待整个周期。
- 没有实际内容变化时不做空提交。

每次保存须做到：

1. 提交相关笔记、看板、论文源文件、必要计算与证书、文献及索引，明确它们的数学状态；未证草稿可以按 [C/E/O] 保存。
2. 本版目标文件位于 Git 根目录外。保存目标变更时，须将本版及必要历史归档同步到仓库内的版本化路径，例如 goals/，再纳入提交；不要误以为仓库外的文件已被 Git 保存。
3. 检查本次差异并运行与变更相关的验证。排除临时渲染、缓存和下载残片；稳定论文版本需要时再重编 PDF，不为每次记录更新重跑全部数学计算。
4. commit 信息说明保存了什么以及重要状态变化。推送后确认远程对应提交，记录分支、commit SHA 与同步结果。
5. 推送失败时保留已完成的本地 commit，记下错误与未同步状态并在网络恢复后重试；不要把本地提交成功记成推送成功。遇到远程更新先正常处理差异，不用强制推送覆盖他人或既有历史。

网络连接或推送遇到问题时，可按原 GOAL 第九节的提示尝试本机代理 http://127.0.0.1:10808。在当前 PowerShell 会话中设置：

```powershell
$env:http_proxy = "http://127.0.0.1:10808"
$env:https_proxy = "http://127.0.0.1:10808"
```

若使用 CMD，原提示对应的命令为：

```cmd
set http_proxy=http://127.0.0.1:10808
set https_proxy=http://127.0.0.1:10808
```

设置仅对当前终端会话及其启动的进程生效；设置后重试文献下载或 Git 推送，并核实操作结果。

版本保存与数学验收分开。commit、push、CI 或 PDF 编译成功仅说明相应保存/检查完成，不证明 RH、原创性或论文级定理成立。

## 十、当前目标、较远期目标与整个GOAL的终止标准

### A. 当前目标：周期验收，验收后继续

当前先结算第四节A的中断验证，再连续执行第四节B的F₁有限研究周期。周期4–12及既有F₁框架、讲义均为已完成基线；以后周期按同样原则写有限任务单。
每次结算必须有：

1. 准确对象、参数、前提、原始重数及完整有符号账本；至少完成一个实质推导／反例／实际输入核查。
2. 成果、失败范围和未证输入分开；数学动作而非文档数量构成轮次。
3. 候选的证明、必要证据、原始文献对应及独立复核异议闭环；未审草稿保留准确状态。
4. 对实际零点或结构目标的净价值说明，下一有限任务／切换理由明确。
5. 目标历史、笔记、文献和索引及时保存，定期commit/push并核验远程SHA。

A全部满足，只能登记“本周期已结算”，不能调用GOAL complete。
一个候选无净价值就切换；有条件性小进展就继续验证其真实算术接口，不另建一个容易完成的GOAL替代本目标。

### B. 较远期目标方向

以下为并列方向；不要求同时解决所有方向才有意义，但每项结论必须与所声称的强度相符。

| 方向 | 目标结果 | 当前真正缺口／证据要求 |
|---|---|---|
| RH及相关L函数 | 给实际Riemann zeta的非循环完整证明；推广时准确标明对象与范围 | 实际正性／谱可见性、显式公式及Gamma和极限不能预设；完整依赖独立复核 |
| 零点比例与零密度 | 无RH假设地改进简单临界线、不同点或离线零点计数的可证明界 | 更新并核查比较基线，分母／重数／区间统一；有限常数或未审最新声明不直接当定理 |
| 非零区域 | 对实际zeta／指定L族扩大已知非零区域，或给有实质增益的显式高度范围／常数 | 所有高度量词、例外零点、导子依赖和已有最好适用界清楚；不能仅在假想模型里排零 |
| 有实质内容的Weil型结构 | 构造与实际算术连接的新正性、对应、上同调或谱结构，并证明此前没有的强制性后果；或严格缩减这一构造的关键未证输入 | 仅定义RH等价正性、重述GNS／纯谱／Rosati或改符号不够；允许独立证明等价条件包存在，须给新算术桥梁、非循环存在性或真正更弱且可验证的输入 |
| 实际高矩／显式公式预算 | 无RH证明当前未证的合并有符号高阶预算、关键局部相关或Gamma控制，并接合一个实质算术后果 | 四阶候选矩和数值校准仍非事实；通道合并、均匀误差及真实窗口一致 |
| 有效机制的严格边界 | 排除一个与实际问题有关、此前未被排除的有实质规模的方法类，同时给出更精确的可行性分界或可推进的不同机制 | 不是一个孤立线代反例或旧计数模型变体；须说明对上述核心目标的实际影响及没有被排除的逃逸条件 |

可按证据增加其他较远期方向，例如有效算术谱实现、可认证的局部正性准则或适用于数域的一致迹机制。
新增方向必须说明为何与上述目标相当，不能仅因较容易完成而降低整个GOAL的门槛。

### C. “显著进展”及完成审计

整个GOAL可完成，当且仅当B中至少一项目标实现，或取得达到以下标准的显著进展，并完成D：

1. 相比本版启动时已确认的320、351／355、361–363、A–E与G0–G8 v1.1及26项形式化检查等基线，有独立、非重复的关键数学输入。旧候选失败审计与重启归档本身不算较远期显著进展。
2. 该输入已接合实际算术对象／关键结构存在性，并带来严格量化的净改进，
   或消除一个长期主瓶颈；若仍有条件，须证明条件严格变弱且验证其非空实际适用范围，
   不能仅将一个未证几何条件替换成另一个未证矩阵预算。
3. 若走严格障碍方向，需达到B末行的规模与实际意义；不能以多份小障碍累积冒充核心瓶颈的解决。
4. 完整推导、原始来源、新旧结果对比及内部独立复核已经闭环；对于可能影响RH／纪录的结果，
   另作一次不依赖原推导组织方式的独立逆审。外部同行评审与世界优先权只按真实状态陈述。

新的条件性算子引理、较小log优化、例行归档或完成4–8轮可以是实质工作，
但若未通过C就只是进度，GOAL继续active。数学困难和目前没有突破不是权限阻塞。

### D. 保存、动态修订及停止纪律

1. 达到C后逐项核对本版完整要求、推导与全部依赖、实际效果、文献版本、远程SHA和下一问题；
   证据不够就继续，不因预算、时长或候选数量将目标标成完成。
2. 用户已授权按新情况继续修订本文件，无须每周期重新确认。实质路线变更先保存旧版并写理由，
   维持B/C的研究强度；术语／排版修正不必制造重复快照。
3. 只有真正外部阻塞并达到工具规定的连续阻塞审计门槛才能标blocked；
   未解出的数学问题、单一来源失效或一个候选失败都应先继续独立研究／正常切换。
4. 一个回复结束、上下文切换、周期结算或Git推送不等于整个GOAL完成；
