# 可恢复的长期重型研究流程

适用于数学、算法、科学调查和工程。保存能决定下一步的状态，
证据留在原件，摘要不当证明。

## 分层与唯一来源

| 层 | 内容 | 更新时机 |
|---|---|---|
| Goal | 原目标、强度、完整验收、用户约束 | 实质修订 |
| STATE | 当前原因、瓶颈、唯一合同、下一动作、未知 | 每轮／中断前 |
| 战略 | 独立来源→实际比较→全域极限→后果的缺口图 | 瓶颈改变 |
| 合同 | 对象、量词、独立输入、负对照、预算、止损 | 任务开始／修改 |
| 证据 | 推导、来源版本、数据、代码、检查范围 | 取得时 |
| 决策 | 为什么选／停／转及重新准入条件 | 路线变化 |
| 节奏 | 已完成迭代及周期复盘 | 完整研究轮结算 |

STATE只引用原件，轮数只在cadence。哈希证明文件同一性，不证明数学。
Goal不积累进展；旧NEXT／PROGRESS不再是当前指令。

## 每轮开始与一页合同

检查文件、工作树和实际运行态，再回答：
用户最终要什么、哪些约束有效？当前合同为何值得做？
上一轮新增什么独立输入、哪个前件仍未付？
今天改变哪个缺口，有没有费用更小、信息更多的检验？
摘要与原件不符时记未知，源变动区分换行／版本／意义，不能无声消费旧审查。
文件active不能代替get_goal或实际进程。

合同写宏观贡献；对象、量词、域、符号、重数、极限顺序；
独立输入／一级来源和open前件；最便宜反例／负对照；
成功、失败、信息不足的交付；1–2轮预算、晋级与停止条件。
数值先冻结，改参数先留新版和原因，旧不利结果不删除。
对象存在不等于标签定义，有限对象不等于全域。

## 执行和结算

独立推导、反例与来源可并行，文件所有权分开，主代理核对前件后合并。
小修改不机械三审；重要结论需不同组织方式逆审。
适用检查通过后不机械扩大／重复。
证据区分proved、conditional、cited、experiment、obstruction、open；
每项附范围，执行完成不能把experiment改为proved。

结束用约五句话留下：问题、真实新增、未付前件、宏观影响、下一动作。
更新合同／STATE的证据、未知和进程，完整迭代才推进cadence一次。
转向写短决策，不让脚本凭退出码宣告数学进展。
运行 python scripts/research_state.py check 及 show；
checkpoint保存所引用核心文件哈希及快照，不认证证明或工具运行态。
按授权提交并核对远程SHA，只记可核实基线。

## 两个时间尺度及恢复

合同1–2轮止损，整体每4–8轮复盘，默认6。
复盘问瓶颈是否缩小、独立来源是否可用、替代路线价值、
最值得失败的检验、什么证据会推翻优先级。
转向不降低原目标，合同止损不重置周期；
重启旧路线须新来源、不同对象／拓扑或新有符号估计。

压缩／中断后按AGENTS读STATE→Goal→合同→最新决策→所需原件，
继承暂停路线、前件、停止条件和轮数，再核查未完成进程。
未知进程先核查，不重跑昂贵执行或冒称结果已保存。
用户补充默认指导原任务，明确取消／不兼容新目标才替换。

这里采用工作区文件与检查点，不改平台压缩设置，不声称SDK memory或自动钩子已实现。
