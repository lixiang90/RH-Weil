## Windows containment, hidden console metadata and unexpected descendants

The native backend uses a new unnamed kill-on-close Job Object. A
STARTUPINFOEX attribute list supplies JOB_LIST and an explicit list of only the
three inherited standard handles. CreateProcessW receives the exact Python
executable and a separately quoted fixed argv, with CREATE_SUSPENDED,
EXTENDED_STARTUPINFO_PRESENT and CREATE_NO_WINDOW. The child enters the job
atomically during creation. PID/command/freeze/READY metadata are saved before
ResumeThread. There is no shell, visible interactive console, delayed job
assignment race or opportunity to escape before the job is installed. Closing
the observer's noninherited job handle kills associated processes; normal and
failure paths also explicitly terminate/wait for the whole job.

This mechanism follows Microsoft's [JOB_LIST guidance](https://devblogs.microsoft.com/oldnewthing/20230209-00/?p=107812/)
and [attribute documentation](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute).
The [Job Object documentation](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
describes kill-on-close and inheritance; the code enables neither breakaway
flag. Native structure/API types follow [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)
and [extended job limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information).
These are implementation sources, not mathematical primary literature or new
premises for the Weil comparison. No PDF or mathematical library entry is added.

Actual harmless OS tests revealed that hidden Python also creates conhost.exe
inside the Job. Treating TotalProcesses>1 as science incorrectly killed even a

is unchanged. OS console activity belongs to observer overhead, rather than a
second scientific process charge. Unknown/unclassified/exited-before-typing
processes and all other descendants cause a technical STOP and whole-tree kill.

An unexpected scientific descendant could overlap its parent; a single wall

count while leaving descendants=false. The old exception receipt would then

explicitly incomplete on exceptions. After terminating the Job and waiting for
